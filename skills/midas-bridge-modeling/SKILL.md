# MIDAS 桥梁自动化建模 Skill

用 MIDAS Civil NX 自动建桥梁有限元模型。**当前落地：变截面预应力混凝土连续箱梁（悬臂浇筑 FCM）**；
架构按桥型/工法可插拔设计（施工方法库 + 截面库 + 验算项随桥型扩展）。

> **全程示例桥（"例桥"）**：各 reference 文档中凡称"例桥"，均指同一座桥——**变截面预应力混凝土连续箱梁 70+100+70 m、桥面全宽 16 m、公路-I 级、悬臂浇筑(FCM)、单箱单室 NCE2**。该桥已在 MIDAS **实建并验证**，各模块示例里的节点/材料/截面/JSON/回读值**全部是它的真实数据**。该桥的**模型（.mcb/.mct）与设计图纸已内置** `assets/示例/变截面连续箱梁桥-FCM-NCE2/`（见其 `README.md`）。**例子只引用 skill 内部资源，不依赖任何外部文件**（无需 `work/`、原始 .mcb 或 .pdf）——目的是让任意全新会话**只凭 skill 就能照着把这部分建出来**。

## 工作流（五步）

```
① 用户基本信息（桥型/跨径·跨数/桥面宽/截面/施工方法/荷载等级）
        ▼
② 决策文档（人审层）—— LLM 据信息填《reference/决策文档模板.md》，每值带规范出处；用户审"值与出处"
        ▼  ← 决策占建模 80% 工作量，必须人审通过再建
        ▼  ★决策阶段无先后：施工方法→施工阶段→结构组/荷载组/边界组/节点单元划分须通盘协调、彼此照应（详见模板首段）
③ 建模 —— 按决策文档逐章，对应 `reference/建模模块/<部件>.md`（端点/JSON/映射/实测例），建模、回读自检、存盘
        ▼
④ 分析 + 待验算层反算 —— 取 MIDAS demand → 引擎反算钢束/钢筋/箍筋首版 → 录入 → 重分析
        ▼
⑤ 验算微调 —— 自建 JTG 引擎诊断 + 外部 CDN 主控表判据，改模型→重分析→复核，迭代至主控项全部满足
```

**关键非线性**：第②步**确定层**（材料/几何/荷载/边界/阶段，对应 S1–S12）信息够就一次人审定；
**待验算层**（钢束/钢筋/箍筋/竖向预应力，对应 S11/S13）真值回 MIDAS/CDN，纸面只给首版模板+反算引擎口径，主控项全部满足靠 ④⑤ 迭代。

## 核心准则（先于一切）

1. **参数溯源**——确定性参数（材料强度、车道折减系数、温度梯度、作用组合系数、验算限值等）须以现行规范或权威信源为依据，不以语言模型记忆为准。规范已覆盖者查 `reference/code/` 与 `reference/code_tables.md`；规范未予明确者，经权威渠道（含联网检索官方规范、行业标准、学术文献）核实后采用，并标注出处。

2. **单位制统一**——建模之初以 `PUT /db/UNIT` 显式设定统一单位制（本 skill 采用 kN-m：`{"Assign":{"1":{"FORCE":"KN","DIST":"M","HEAT":"KJ","TEMPER":"C"}}}`）；其后各量纲量（节点坐标、截面尺寸、荷载、位移等）均按该单位制直接录入，无需换算。MIDAS 依当前单位制解释所录数值，故操作既有模型或回读结果前，应先以 `GET /db/UNIT` 核实当前单位制；变更单位制经 `PUT /db/UNIT` 即可，既有数值由 MIDAS 自动换算。

## 建模顺序总览（详见各建模模块；决策文档逐章对应）

```
确定层(②人审定)：
单位 → 节点 → 材料 → 设计截面+变截面 → 单元 → 变截面组 → 结构组 →
边界/支承 → 施工阶段荷载(静力工况+荷载组+隔板/挂篮/湿重) → 二期恒载+温度 →
计算跨径+有效宽度+移动荷载 → 收缩徐变+支座沉降 → 施工阶段 → 分析控制(三表含汽车冲击系数)
待验算层(④⑤迭代)：
预应力束(S11配束，先于组合，影响弹性内力) → 荷载组合 → 普通钢筋/箍筋(引擎反算→/db/RPSC 录入) →
验算微调(自建引擎+CDN，迭代至主控项全部满足)
```

六条**硬依赖**（各模块「★硬依赖」处详述）：① 单位先于材料；② 变截面必在单元之前；③ 变截面组(TSGR)必在单元之后；④ 支承在节点之后、落墩心；⑤ 荷载组+工况先于自重/集中力、全部荷载先于施工阶段；⑥ 收缩徐变 TDMT→TMAT→EDMP、整步先于施工阶段分析。

## ★建模纪律（务必先读；违反轻则写入失败、重则 MIDAS 崩溃）

1. **严格按上表顺序逐步建，不得跳步、不得改序、不得并步。** 每一步都有硬依赖前置（如：有效宽度在"计算跨径"之后、"车道线"之前；变截面在单元之前）。**每建一步即 `GET` 回读自检，通过再进下一步。** 跳步/改序或漏字段会令 MIDAS 内部状态不一致而崩溃——真实教训：`/db/SPAN` 只写 `SPAN_LIST`、漏 `SPAN_BASE_ITEMS`（单元→支点映射），产出"分配单元为空"的跨度信息，随后建车道线即拖垮 MIDAS（详见 `建模模块/移动荷载.md` SPAN 例）。

2. **不得用 API 代劳 GUI 步骤；也不得为"省事/求精确"打开示例模型抓数据回填目标模型。** 示例模型（`assets/示例/…`）的定位是**编写与校核本 skill 的实测出处**，不是目标模型的数据源——克隆它既跳过人审、又会带入与本桥不符的量。确定量回决策文档/规范，几何/线形按模块反算，GUI 步骤交用户。

3. **★用户 GUI 操作点（共 3 处）：遇到必须停下、提示用户在 GUI 完成，`GET` 回读确认后再续建；严禁 API 代写或从示例模型克隆。**

| GUI 步骤 | 所在章 | 建模位次 | GUI 菜单路径 | 产物 / 说明 |
|---|---|---|---|---|
| 截面有效宽度 | Ch10 移动荷载 | 计算跨径**之后**、车道线**之前** | 结构 → PSC 桥梁 → 有效宽度 → 选规范 **JTG3362-2018** → 自动生成 | 生成 `/db/EWSF`（各截面翼缘折减系数）+ **自动生成边界组 `WZ_EW_1`**（施工阶段"成桥"激活）；二者均 MIDAS 自动产物，**不得手写** |
| 逐单元理论厚度 EDMP | Ch11 收缩徐变 | TDMT→TMAT **之后** | 特性 → 修改特性 →「构件的理论厚度」+「中国标准」→ 全选单元应用 | 变高段 `h=2A/u` 逐元精确积分；`/db/EDMP` 的 API 路径仅供**核验**（纯自算约 1% 偏差） |
| 荷载组合 | Ch16 荷载组合 | 钢束建成、分析已跑出各效应之后 | 荷载组合对话框 → 混凝土设计 → 自动生成 → 选设计规范 **JTG** | 按 JTG D60 一次生成全部组合（含分项系数）；`/db/LCOM-CONC` 的 API 路径为 fallback，系数仍须逐项对规范 |

> 上表任一步骤，**LLM 的动作是"提示用户在 GUI 完成 → 等待 → `GET` 回读确认"**，不是自己 `PUT`。有效宽度未生成即建车道线或跑施工阶段分析，会"有效分布系数算不出 / 后处理崩溃"（见 `建模模块/分析控制.md`）。

## 环境与约束

- **MAPI Key** 在 Windows 用户级环境变量 `MIDAS_MAPI_KEY`/`MIDAS_MAPI_BASEURL`；用 `[System.Environment]::GetEnvironmentVariable("...","User")` 载入，**从不硬编码、不回显**。
- 跑 python 前设 `PYTHONIOENCODING=utf-8`；中文输出写 UTF-8 文件不写控制台（midas_civil 导入横幅含 emoji，GBK 控制台会崩）。MCT/OUT 为 **GBK** 编码。
- 带单位取值（μ/k/σ、wobble k 的 1/长度最易踩）按当前 `/db/UNIT` 录入（核心准则 2）；本 skill 全程 kN-m。
- 探包/查 API 用静态读源，不执行可能崩 MIDAS 的代码；**永不 kill 正在 API 调用中的 python**（wedge 风险）。
- 改完模型必 `POST /doc/ANAL` 重分析、`POST /doc/SAVEAS` 存盘；磁盘 `.mcb` 为事实源，活动模型会漂移。
