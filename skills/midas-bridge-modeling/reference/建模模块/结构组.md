# 结构组（建模模块）

> **流程**：把单元/节点按**施工浇筑节段**分组（`/db/GRUP`），供施工阶段逐拍激活（`ACT_ELEM`）。是 FCM 悬浇建模的骨架。
> **★建模次序（独立一步）**：**单元 → 变截面组 → 结构组 → 边界**。结构组**必须先于边界、先于施工阶段**——边界组激活、阶段 ACT/DACT 都按结构组名引用。
> **★硬依赖**：① 单元先建（组按单元号引用）；② 本步先挂各组的**梁节点**；虚拟支座节点（78–89）待「边界」建成后**补挂**入对应组（主墩虚拟节点→`0#块`、边墩虚拟节点→`边跨现浇`）。
> **★节段划分逻辑不在本模块**：每个节段含哪些单元、左右墩如何对称配对，由**施工方法**决定，见「施工方法/悬臂浇筑」；本模块只讲 GRUP 怎么 PUT。

## 1. API 接口
| 项 | 内容 |
|---|---|
| 端点 | `/db/GRUP` |
| 写入 | `PUT /db/GRUP`，body = `{"Assign": {<id>: {NAME, P_TYPE, N_LIST, E_LIST}}}` |
| 回读 | `GET /db/GRUP` → `{"GRUP": {<id>: {…}}}` |

> **★写入注意**：id 1 是系统活动组 `TEMP_DATA`（含全部单元、渲染遗留）。**PUT 前先 `DELETE /db/GRUP` 清存量**（系统组可删），再从 id 1 写功能组——否则 id 1 只改名不改元素、残留全单元组。

## 2. JSON 各字段含义
```jsonc
{ "NAME":"节段1",          // 组名——施工阶段 ACT_ELEM 按此名激活，须稳定
  "P_TYPE":0,              // 0=结构组（区别于边界组/荷载组）
  "N_LIST":[19,20,26,27,51,52,58,59],   // 本组节点（先挂梁节点；虚拟支座节点边界后补挂）
  "E_LIST":[19,26,51,58] }              // 本组单元
```
> **要点**：① `NAME` 是施工阶段的接口，**改名会断开阶段引用**，须与决策文档/施工方法一致。② FCM 双悬臂对称：一个 `节段N` 组同时含**左墩两侧 + 右墩两侧**的单元（如 `节段1` = `[19,26,51,58]`，左墩 23 两侧 19/26 + 右墩 55 两侧 51/58）。③ `0#块`/`边跨现浇` 的 `N_LIST` 在边界建成后追加虚拟支座节点。

## 3. 映射与格式
- **数据来源**：决策文档「结构组」章 + 「施工方法/悬臂浇筑」的节段划分表（节段数 N、每组单元）。
- **组构成（FCM）**：`0#块`（墩顶现浇段）+ `节段1..N`（悬浇节段，对称）+ `边跨现浇`（支架现浇段）+ `边跨合拢` + `中跨合拢`。
- 每组 `E_LIST` 按几何分区取单元；`N_LIST` 取这些单元的梁节点（去重）。

## 4. 例子
**例桥**：变截面预应力混凝土连续箱梁 70+100+70 m，**双主墩 FCM、每墩悬臂 12 节段（左右对称同步）**（数据由 `GET /db/GRUP` API 实测）。**结构组 16 个**：`0#块`、`节段1`…`节段12`、`边跨现浇`、`边跨合拢`、`中跨合拢`。

**① 真实写入 `PUT /db/GRUP`（节选；写前先 `DELETE /db/GRUP` 清系统组）**
```json
{"Assign": {
  "1": {"NAME":"0#块","P_TYPE":0,
        "N_LIST":[20,21,22,23,24,25,26,52,53,54,55,56,57,58,79,81,87,89],
        "E_LIST":[20,21,22,23,24,25,52,53,54,55,56,57]},
  "2": {"NAME":"节段1","P_TYPE":0,"N_LIST":[19,20,26,27,51,52,58,59],"E_LIST":[19,26,51,58]},
  "15":{"NAME":"边跨合拢","P_TYPE":0,"N_LIST":[6,7,8,70,71,72],"E_LIST":[6,7,70,71]},
  "16":{"NAME":"中跨合拢","P_TYPE":0,"N_LIST":[38,39,40],"E_LIST":[38,39]}}}
```
> `0#块` 的 `N_LIST` 已含虚拟支座节点 79/81/87/89——这是「边界」建成后补挂的结果（本步初建时只挂梁节点 20–26/52–58）。

**② Python 驱动（从决策文档「结构组」表批量建；`MidasAPI` 约定同「节点」模块）**
```python
MidasAPI("DELETE", "/db/GRUP", {})                 # ★先清系统活动组(id1)
grup = {}
for i, (nm, elems, nodes) in enumerate(grup_rows, 1):   # 决策文档/施工方法给 (组名, 单元, 节点)
    grup[i] = {"NAME": nm, "P_TYPE": 0, "E_LIST": elems, "N_LIST": nodes}
MidasAPI("PUT", "/db/GRUP", {"Assign": grup})      # 16 组
```

**③ 核对（API 实测 GET）**：`GET /db/GRUP`=16 结构组 ✓；`节段1` E_LIST=`[19,26,51,58]`（双墩对称各 2 单元）✓；`0#块` 含虚拟支座节点 79/81/87/89 ✓；组名与施工阶段 `ACT_ELEM.GRUP_NAME` 一一对应 ✓。
