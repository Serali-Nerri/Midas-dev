# 移动荷载（建模模块）

> **流程**：定义车辆活载的完整管线——**移动荷载规范**(`/db/MVCD`) → **计算跨径**(`/db/SPAN`) → **截面有效宽度**(`/db/EWSF`) → **车道线**(`/db/LLANch`) → **车辆/活载**(`/db/MVHL`) → **移动荷载工况**(`/db/MVLDch`，含多车道横向折减)。
> **★硬依赖（顺序不可打乱）**：① 规范先设（CHINA），车辆/折减系数才按 JTG 取；② 跨径先于有效宽度（有效宽度系数依跨径），且 `/db/SPAN` 须含 `SPAN_BASE_ITEMS`（漏则空跨度信息、后续崩溃）；③ **有效宽度（GUI 步骤，见下）必须在车道线之前完成**——否则 EWSF/`WZ_EW_1` 缺失，车道线、工况乃至施工阶段分析都会报错或崩溃；④ 车道线先于工况（工况按车道名选车道）。**本模块严格按 `规范→跨径→有效宽度(GUI)→车道线→车辆→工况` 推进，每步 `GET` 回读自检。**
> **★有效宽度（两条路径，GUI 优先）**：
> - **默认 = GUI 自动生成**：菜单 **结构 → PSC 桥梁 → 有效宽度** → 弹窗**选择规范**（JTG）→ 点**自动生成**。MIDAS 按规范+跨径算出各截面翼缘折减系数并写入。**应优先提示用户在 GUI 完成此步**。
> - **可选 = API 写入（fallback）**：用户声明走 API 时，按规范（JTG D60 §4.2.2 翼缘有效宽度）算出各截面折减系数，`PUT /db/EWSF` 写入（`/db/EWSF` 是可读写真实表，按截面存系数）。**★注意：边界组 `WZ_EW_1` 是 GUI「自动生成」路径的产物，不是手写对象；走 API fallback 时 `WZ_EW_1` 须已存在，否则 `PUT /db/EWSF` 直接报错（400）。故即便走 API，通常仍应先由 GUI 生成一次。默认应直接提示用户在 GUI 完成、不走此 fallback。**
> **★冲击系数（汽车）不在本模块**：属「分析控制」三表之一（`/db/mvctch`，需特征值分析得基频后定），见「分析控制」模块。

## 1. API 接口
| 项 | 端点 | 说明 |
|---|---|---|
| 移动荷载规范 | `/db/MVCD` | 设 `CODE="CHINA"` |
| 计算跨径 | `/db/SPAN` | 各跨理论跨径 + 支点单元映射 |
| 截面有效宽度 | `/db/EWSF` | 按截面的翼缘折减系数（GUI 生成 / API 写入）|
| 车道线 | `/db/LLANch` | 车道/人行道几何（**注：`/db/LLAN` 是空壳，数据在 `LLANch`**）|
| 车辆/活载 | `/db/MVHL` | 车辆荷载（CH-CD 车道荷载 / CH-RQ 人群）|
| 移动荷载工况 | `/db/MVLDch` | 工况 + 多车道横向折减 + 选定车道（**`/db/MVLD` 是空壳，数据在 `MVLDch`**）|

> **命名规律**：带 `ch` 后缀的端点（`LLANch`/`MVLDch`/`mvctch`）= **按当前规范展开的详表**，真实数据在此；不带后缀的 `LLAN`/`MVLD`/`MVCT` 多为空壳容器。

## 2. JSON 各字段含义
```jsonc
// 规范 /db/MVCD：{"1":{"CODE":"CHINA"}}
// 跨径 /db/SPAN：
{ "1": { "NAME":"1", "bEXACTSPAN":false, "DIRECTION":0, "SECTTYPE":0,
   "SPAN_LIST":[1.5,68.5,100,68.5,1.5],          // 各跨理论跨径（含桥台外伸 1.5）
   "SPAN_BASE_ITEMS":[{"ELEM_KEY":1,"SUPPORT":2},{"ELEM_KEY":2,"SUPPORT":0}, … ,{"ELEM_KEY":76,"SUPPORT":1}] } }
   // ★SPAN_BASE_ITEMS 必给：车道线经过的**全部**梁单元逐个列出，SUPPORT 标支点位置——
   //   SUPPORT：0=非支点 / 1=支点在该单元 I 端 / 2=支点在该单元 J 端。
   //   仅写 SPAN_LIST、漏 SPAN_BASE_ITEMS → 产出"分配单元为空"的跨度信息，随后建车道线会拖垮 MIDAS。
// 有效宽度 /db/EWSF（按截面 id；I/J 两端各一组折减系数）：
{ "<截面id>": { "ITEMS":[ {"ID":1,"GROUP_NAME":"WZ_EW_1",
     "LYSCALE":1, "ZTSCALE":1, "ZBSCALE":1,        // I 端：翼缘(Ly)/顶板(Zt)/底板(Zb)折减
     "bJ":true, "LYSCALE_J":0.9079, "ZTSCALE_J":1, "ZBSCALE_J":1 } ] } }   // bJ=true→J 端另给
// 车道线 /db/LLANch（★COMMON 必须给全 10 键——缺 SKEW_START/SKEW_END/OPT_AUTO_LANE/ALLOW_WIDTH 会让 MIDAS 读到未初始化值而"程序终止/崩溃"，不是报错，真实教训）：
{ "<id>": { "COMMON":{ "LL_NAME":"南北向车道1", "LOAD_DIST":"LANE", "GROUP_NAME":"",  // 横向分布方式
     "SKEW_START":0, "SKEW_END":0,           // 斜交角(直桥=0)——★缺则崩
     "MOVING":"FORWARD", "WHEEL_SPACE":1.8,   // 行车道轮距 1.8；人行道(人群面荷载、无轮载)取 0
     "WIDTH":3, "OPT_AUTO_LANE":false, "ALLOW_WIDTH":3 },   // ★缺 OPT_AUTO_LANE/ALLOW_WIDTH 则崩；OPT_AUTO_LANE=false 时 WIDTH/ALLOW_WIDTH 不参与定位
   "LANE_ITEMS":[ {"ELEM":1,"ECC":1.75,"SPAN":100,"SPAN_START":true,"SCALE_FACTOR":1}, … ] } }  // ECC=车道偏心(距中线)；全 76 单元逐个列，SPAN_START 仅首元 true
// 车辆 /db/MVHL（MVLD_CODE=3 中国；★VEHICLE_LOAD_NUM=1 必给，缺则"Wrong Field"）：
{ "<id>": { "MVLD_CODE":3, "VEHICLE_LOAD_NAME":"CH-CD", "VEHICLE_LOAD_NUM":1,
            "VEHICLE_TYPE_NAME":"CH-CD", "STANDARD_CODE":"JTGB01-2014" } }   // CH-CD=公路车道荷载；CH-RQ=人群(另加 "VEH_CN":{"CROWD_WIDTH":1})
// 移动荷载工况 /db/MVLDch（★COMMON 8 键必给全——缺 DESC/SCALE_FACTOR_O/SCALE_FACTOR_N/LOADING_EFFECT 会报"数据不存在"）：
{ "<id>": { "LCNAME":"汽车", "DESC":"", "OPT_AUTO_OPTIMIZE":false, "BRIDGE_TYPE":2,
   "SCALE_FACTOR_O":[1,1,0.8,0.67,0.6,0.55,0.55,0.55],       // 旧规多车道横向折减
   "SCALE_FACTOR_N":[1,1,0.78,0.67,0.6,0.55,0.52,0.5],       // 新规多车道横向折减
   "SCALE_FACTOR_JTG":[1.2,1,0.78,0.67,0.6,0.55,0.52,0.5],   // ★JTG 多车道横向折减(按加载车道数 1,2,3…)
   "LOADING_EFFECT":0,                                        // ★必给
   "SUB_LOAD_ITEMS":[ {"VEHICLE_CLASS":"CH-CD","VEHICLE_TYPE":"VL","SCALE_FACTOR":1.15,
       "MIN_NUM_LOADED_LANES":1,"MAX_NUM_LOADED_LANES":4,
       "SELECTED_LANES":["南北向车道1","南北向车道2","北南向车道1","北南向车道2"] } ] } }
```
> **要点**：① 有效宽度系数 `LYSCALE/ZTSCALE/ZBSCALE` 是**翼缘/顶板/底板的有效宽度折减比**（1=不折减），按截面、按 I/J 端给。② `SCALE_FACTOR_JTG` 是**多车道横向折减系数**（JTG D60 §4.3.1，1/2 车道=1.2/1.0、3 车道 0.78…），随加载车道数取。③ 车道 `ECC`=车道中线距桥梁中线的横向偏心（人行道 ±7.5、车道 ±1.75/±5.25）。

## 3. 映射与格式
- **规范**：`/db/MVCD` 固定 `CODE="CHINA"`（中国 JTG）。
- **跨径**：`SPAN_LIST`=各跨理论跨径（端部桥台外伸段计入，例桥 `[1.5,68.5,100,68.5,1.5]`）；**并须同时给 `SPAN_BASE_ITEMS`**——车道线经过的全部梁单元逐个列出、在支承处标 `SUPPORT`（1=I 端支点 / 2=J 端支点，其余 0）。**二者缺一（尤其漏 `SPAN_BASE_ITEMS`）会写出"分配单元为空"的跨度信息，且随后建车道线会拖垮 MIDAS。**
  > **计算跨径 / 桥梁跨度（车道线 `SPAN`、`SPAN_LIST` 之依据，JTG D60-2015 §4.1.2 / JTG 3362-2018）**：**设支座的桥孔，取相邻两支座中心之间的距离；不设支座的（如刚构、拱），取上、下部结构相交面之间的水平距离。** 例桥主墩间设支座 → 主跨计算跨径 = 墩心距 = 100 m；边跨支座（节点 2/76，距梁端 1.5 m）至主墩支座（节点 23/55）= 68.5 m（+ 桥台外伸 1.5 m 合 70 m 名义跨）。车道线各 `LANE_ITEM.SPAN` 统一取**最大计算跨径 100 m**（供 JTG 冲击/加载长度取用）。
- **有效宽度**：优先 GUI 自动生成；API 路径按 JTG 算系数 `PUT /db/EWSF`（按截面）。
- **车道线**：决策文档「移动荷载」章给车道布置（车道数、宽度、横向偏心 ECC）。车道 `WIDTH=3`、`WHEEL_SPACE=1.8`。
- **车辆**：公路-I 级 → 车道荷载 `CH-CD` + 人群 `CH-RQ`。
- **工况**：每类活载一工况（汽车/人群），`SCALE_FACTOR_JTG` 按规范填，`SUB_LOAD_ITEMS` 选定参与车道与加载车道数范围。

## 4. 例子
**例桥**：变截面预应力混凝土连续箱梁 70+100+70 m，桥面全宽 16 m、公路-I 级 + 人群（数据由 `GET /db/*` API 实测；例子 kN-m，长度 m——核心准则 2）。

**车道布置（`GET /db/LLANch`，6 条 = 4 车道 + 2 人行道；WIDTH=3、WHEEL=1.8、LOAD_DIST=LANE）**

| id | 名称 | 横向偏心 ECC |
|---|---|---|
| 2 / 3 | 南北向车道1 / 2 | +1.75 / +5.25 |
| 4 / 5 | 北南向车道1 / 2 | −1.75 / −5.25 |
| 1 / 6 | 南-北 / 北-南 人行道 | +7.5 / −7.5 |

**① 规范 `/db/MVCD` + 跨径 `/db/SPAN`**
```json
{"Assign": {"1": {"CODE": "CHINA"}}}
```
```json
{"Assign": {"1": {"NAME":"1","bEXACTSPAN":false,"DIRECTION":0,"SECTTYPE":0,
  "SPAN_LIST":[1.5,68.5,100,68.5,1.5],
  "SPAN_BASE_ITEMS":[{"ELEM_KEY":1,"SUPPORT":2}, … ,{"ELEM_KEY":23,"SUPPORT":1}, … ,
                     {"ELEM_KEY":54,"SUPPORT":2}, … ,{"ELEM_KEY":76,"SUPPORT":1}, … ]}}}
```
> **★ `SPAN_BASE_ITEMS` 必给（否则跨度信息为空、后续崩溃）**：列全车道经过的 **76 个梁单元**；支点落在**支承节点 2/23/55/76**，对应单元 **1(J 端,`SUPPORT=2`)、23(I 端,`SUPPORT=1`)、54(J 端,`SUPPORT=2`)、76(I 端,`SUPPORT=1`)**，其余单元 `SUPPORT=0`。
```python
# 支承节点→(单元,端)：节点2=elem1 的 J 端、节点23=elem23 的 I 端、节点55=elem54 的 J 端、节点76=elem76 的 I 端
supp = {1:2, 23:1, 54:2, 76:1}                                    # {单元号: SUPPORT码(1=I端支点/2=J端支点)}
base = [{"ELEM_KEY":e, "SUPPORT":supp.get(e,0)} for e in range(1,77)]   # 全 76 单元，逐个列出
MidasAPI("PUT","/db/SPAN",{"Assign":{"1":{"NAME":"1","bEXACTSPAN":False,"DIRECTION":0,"SECTTYPE":0,
    "SPAN_LIST":[1.5,68.5,100,68.5,1.5], "SPAN_BASE_ITEMS":base}}})
```

**② 有效宽度 `/db/EWSF`（API fallback；GUI 路径见上「概述」）**
```json
{"Assign": {"1": {"ITEMS":[{"ID":1,"GROUP_NAME":"WZ_EW_1",
  "LYSCALE":1,"ZTSCALE":1,"ZBSCALE":1,"bJ":true,"LYSCALE_J":0.9079,"ZTSCALE_J":1,"ZBSCALE_J":1}]},
  "2": {"ITEMS":[{"ID":1,"GROUP_NAME":"WZ_EW_1",
  "LYSCALE":0.9079,"ZTSCALE":1,"ZBSCALE":1,"bJ":true,"LYSCALE_J":0.9849,"ZTSCALE_J":1,"ZBSCALE_J":1}]}}}
```
> 共 76 截面（每梁单元一组）。系数 `LYSCALE` 随翼缘宽/跨径比沿桥变化（墩附近翼缘有效宽度折减大）。**优先让用户走 GUI 自动生成**，把这步交给规范引擎，避免手算系数出错。

**③ 车道线 `/db/LLANch`（1 条车道示例）+ 车辆 `/db/MVHL`**
