# 边界（建模模块）

> **流程**：建**边界组**(`/db/BNGR`) → **虚拟支座节点**(`/db/NODE`，z=−梁高，落到支座垫石顶) → **弹性连接**(`/db/elnk`，虚拟节点 RIGID 连梁形心) → **支承约束**(`/db/cons`，按施工阶段分组施加)。
> **★硬依赖**：① 边界组**先建**——弹性连接/支承都按**组名**引；② 虚拟节点先于引用它的连接/支承；③ 主梁节点先于这一切。
> **★体系转换（FCM 核心）**：悬臂浇筑期墩梁**临时固结**（主墩虚拟节点 `1111110` 全固），成桥时转**永久支座**（释放纵向/转动）。实现 = **同一节点挂多组约束（多 `ITEMS`）**，施工阶段按**边界组名**激活不同组。

## 1. API 接口
| 项 | 内容 |
|---|---|
| 端点 | `/db/BNGR`(边界组) ＋ `/db/NODE`(虚拟支座节点) ＋ `/db/elnk`(弹性连接) ＋ `/db/cons`(支承，**不是 SUPT！**) |
| 写入 | `PUT /db/BNGR` `{"Assign":{<id>:{NAME,AUTOTYPE}}}`<br>`PUT /db/elnk` `{"Assign":{<id>:{NODE,LINK,ANGLE,bSHEAR,DR,BNGR_NAME}}}`<br>`PUT /db/cons` `{"Assign":{<节点>:{ITEMS:[{ID,CONSTRAINT,GROUP_NAME}]}}}` |
| 回读 | `GET /db/BNGR`/`/db/elnk` 全量；**`GET /db/cons` 只返当前激活阶段** → 全量核对走 MCT `*CONSTRAINT` |

## 2. JSON 各字段含义
```
# —— /db/BNGR（边界组，仅命名容器）——
{ "NAME": "主墩弹性连接", "AUTOTYPE": 0 }     # AUTOTYPE=0 普通组

# —— 虚拟支座节点：就是 /db/NODE，关键是坐标 ——
{ "X": 0, "Y": -3450, "Z": -6000 }            # Z = −梁高(到垫石顶)；Y=±横向支座半距

# —— /db/elnk（弹性连接）——
{ "NODE": [89, 23],        # [虚拟支座节点, 梁形心节点]
  "LINK": "RIGID",         # 刚性连接(把梁形心力传到支座点)
  "ANGLE": 0,
  "bSHEAR": false,         # 不设剪切弹簧偏移
  "DR": [0.5, 0.5],        # 剪切弹簧位置比(DRy,DRz)
  "BNGR_NAME": "主墩弹性连接" }   # 所属边界组(须已在 BNGR 建)

# —— /db/cons（支承）——
{ "<节点号>": { "ITEMS": [        # 同一节点多组约束=多 ITEMS（这就是体系转换）
    { "ID": 1, "CONSTRAINT": "1111110", "GROUP_NAME": "主墩固接" },
    { "ID": 2, "CONSTRAINT": "0110000", "GROUP_NAME": "成桥"  } ] } }
```
> **要点**：① **`CONSTRAINT` 是 7 位** `Dx Dy Dz Rx Ry Rz Rw`（1=约束）——**MCT 里是 6 位**，写 API **末尾补 `Rw=0`**（如 `111111`→`1111110`、`011000`→`0110000`）。② **虚拟节点 `Z=−梁高`**——与截面 `OFFSET_PT="CT"`（节点在截面顶）一致，支座落在梁底垫石顶。③ `GET /db/cons` 只给激活阶段态，**全量验证比对 MCT `*CONSTRAINT`**。

## 3. 映射与格式
- **边界组**：决策文档「边界」章列出（本桥功能组 7 个：`主墩弹性连接`/`边墩弹性连接`/`主墩固接`/`0#现浇`/`边跨现浇`/`边跨合拢`/`成桥`）。
- **虚拟支座节点**：每个支座一节点，坐标 = 支座中心：`X`=支座纵向位置、`Y`=±横向支座半距、`Z`=**−梁高**（单位随模型 `/db/UNIT`，见核心准则 2）。
- **弹性连接**：每个虚拟节点 `RIGID` 连到对应**梁形心节点**（主墩→23/55、边墩台→2/76），归入对应弹性连接组。
- **支承约束**：在虚拟节点（及 0#/现浇期的部分梁节点）按**阶段组**施加约束码；**同节点跨阶段不同码 = 体系转换**（固结→固定支座→活动支座）。

## 4. 例子
**例桥**：变截面预应力混凝土连续箱梁 70+100+70 m（数据由 `GET /db/*` API 实测；**例子统一 kN-m**：坐标 m、约束 7 位。单位之初以 `PUT /db/UNIT` 设定，直接录入——核心准则 2）。支座 = 双柱墩 + 桥台，主墩 2 + 桥台 2，每处 2 个支座（横向 ±y）。

**虚拟支座节点（8，Z=−梁高；坐标 m，API 实测 `GET /db/NODE`）**

| 节点 | 位置 | X | Y | Z(=−梁高) | 连梁形心节点 |
|---|---|---|---|---|---|
| 89 / 87 | 左主墩(x=0) | 0 | ±3.45 | −6.0 | 23 |
| 81 / 79 | 右主墩(x=100) | 100 | ±3.45 | −6.0 | 55 |
| 78 / 82 | 左桥台 | −68.5 | ±3.65 | −2.5 | 2 |
| 83 / 88 | 右桥台 | 168.5 | ±3.65 | −2.5 | 76 |

> 主墩 Z=−6.0(梁高 6.0 m)、桥台 Z=−2.5(梁高 2.5 m)；桥台支座 X 内缩 1.5 m（支座距梁端）。N-mm 模型下同表 ×1000。

**弹性连接（8，RIGID）**：`89→23 87→23 81→55 79→55`（主墩弹性连接）｜`78→2 82→2 83→76 88→76`（边墩弹性连接）。

**① `PUT /db/BNGR`（先建边界组）**
```json
{"Assign": {"1":{"NAME":"主墩弹性连接","AUTOTYPE":0},"2":{"NAME":"边墩弹性连接","AUTOTYPE":0},
  "3":{"NAME":"主墩固接","AUTOTYPE":0},"4":{"NAME":"0#现浇","AUTOTYPE":0},
  "5":{"NAME":"边跨现浇","AUTOTYPE":0},"6":{"NAME":"边跨合拢","AUTOTYPE":0},
  "7":{"NAME":"成桥","AUTOTYPE":0}}}
```

**② `PUT /db/NODE`（虚拟支座节点；坐标 m）＋ `PUT /db/elnk`（弹性连接）**
```json
{"Assign": {"89":{"X":0,"Y":3.45,"Z":-6}, "87":{"X":0,"Y":-3.45,"Z":-6},
            "79":{"X":100,"Y":-3.45,"Z":-6}, "78":{"X":-68.5,"Y":3.65,"Z":-2.5}}}
```
```json
{"Assign": {"1":{"NODE":[89,23],"LINK":"RIGID","ANGLE":0,"bSHEAR":false,"DR":[0.5,0.5],"BNGR_NAME":"主墩弹性连接"},
            "5":{"NODE":[78, 2],"LINK":"RIGID","ANGLE":0,"bSHEAR":false,"DR":[0.5,0.5],"BNGR_NAME":"边墩弹性连接"}}}
```

**③ `PUT /db/cons`（支承；右主墩 节点 79，同节点多组 = 体系转换）**
```json
{"Assign": {"79":{"ITEMS":[
  {"ID":1,"CONSTRAINT":"1111110","GROUP_NAME":"主墩固接"},
  {"ID":2,"CONSTRAINT":"1110000","GROUP_NAME":"边跨合拢"},
  {"ID":3,"CONSTRAINT":"0110000","GROUP_NAME":"成桥"}
]}}}
```
> 解读：`1111110`(全固结)=悬臂期墩梁临时固接 → `1110000`(Dx Dy Dz)=固定支座 → `0110000`(Dy Dz)=活动支座(释放纵向 Dx)。**这串就是 FCM 体系转换**。0# 浇筑期还对墩顶梁节点 23/55 直接施 `1111010`(组「0#现浇」)。
> **`ID` 在 PUT 里是本节点内的局部序号**（1,2,3…）；**`GET /db/cons` 回读时返全局流水号**（如某节点 ITEM 的 `ID` 可能是 16、55），别误以为要按它对齐。

**④ Python 驱动（决策文档「边界」表→四端点；`MidasAPI` 约定同「节点」模块）**
```python
# 1) 边界组（先建，后续按组名引）
groups = ["主墩弹性连接","边墩弹性连接","主墩固接","0#现浇","边跨现浇","边跨合拢","成桥"]
MidasAPI("PUT","/db/BNGR",{"Assign":{i+1:{"NAME":g,"AUTOTYPE":0} for i,g in enumerate(groups)}})

# 2) 虚拟支座节点 (节点号: (X, Y, Z=−梁高))  —— 坐标按当前 /db/UNIT；此处 kN-m → m
vn = {89:(0,3.45,-6),87:(0,-3.45,-6), 81:(100,3.45,-6),79:(100,-3.45,-6),
      78:(-68.5,3.65,-2.5),82:(-68.5,-3.65,-2.5), 83:(168.5,3.65,-2.5),88:(168.5,-3.65,-2.5)}
MidasAPI("PUT","/db/NODE",{"Assign":{n:{"X":x,"Y":y,"Z":z} for n,(x,y,z) in vn.items()}})

# 3) 弹性连接 RIGID: (虚拟节点, 形心节点, 组)
links = [(89,23,"主墩弹性连接"),(87,23,"主墩弹性连接"),(81,55,"主墩弹性连接"),(79,55,"主墩弹性连接"),
         (78,2,"边墩弹性连接"),(82,2,"边墩弹性连接"),(83,76,"边墩弹性连接"),(88,76,"边墩弹性连接")]
MidasAPI("PUT","/db/elnk",{"Assign":{i+1:{"NODE":[v,c],"LINK":"RIGID","ANGLE":0,
         "bSHEAR":False,"DR":[0.5,0.5],"BNGR_NAME":g} for i,(v,c,g) in enumerate(links)}})

# 4) 支承约束: {节点: [(7位码, 组名), ...]} —— 同节点多组=多 ITEMS（体系转换）
cons_tab = {79:[("1111110","主墩固接"),("1110000","边跨合拢"),("0110000","成桥")], ...}
cons = {n:{"ITEMS":[{"ID":i+1,"CONSTRAINT":c,"GROUP_NAME":g} for i,(c,g) in enumerate(its)]}
        for n,its in cons_tab.items()}
MidasAPI("PUT","/db/cons",{"Assign":cons})
```

**⑤ 核对（API 实测 GET）**：`GET /db/BNGR` 本模块建的 **7 个功能组**（弹性连接×2/主墩固接/0#现浇/边跨现浇/边跨合拢/成桥）✓；`GET /db/elnk`=8 条 RIGID（虚拟→23/55/2/76），topkey `ELNK` ✓。支承 `GET /db/cons` **只返激活阶段**：成桥阶段实测 = 左主墩固定（87=`1110000`/89=`1010000`）、右主墩与桥台活动（79=`0110000`/81=`0010000`…）——一固多活的纵向释放体系 ✓；**全阶段全量再比对 MCT `*CONSTRAINT`**（6 位→API 7 位）。

> **★关于 `WZ_EW_1`（不在本模块职责内）**：成桥模型 `GET /db/BNGR` 会出现第 8 个组 `WZ_EW_1`，它是**「有效宽度」步骤**的产物（属「移动荷载」模块，非本模块）。**本模块只建 7 个功能组**；第 8 组待有效宽度步骤完成后出现，本步骤不建它、也不应据组数判错。详见「移动荷载」模块。
